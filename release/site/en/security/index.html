Security

How to report a vulnerability to us and how the plugin's updates are protected.

Report a vulnerability

Please do not open a public issue. Use one of two private channels:

  1. GitHub private reporting (preferred): open a report.
  2. Email: security@rt.md.

What to include

  • the plugin, WordPress and PHP versions;
  • what you found and where (file, function or URL);
  • steps to reproduce, ideally a proof of concept;
  • the impact you expect.

Only test on sites you own. Do not access data that is not yours.

Timelines

  • We acknowledge your report within 72 hours.
  • For a confirmed vulnerability we release a fix within 30 days. If it takes longer, we tell you why and agree a date with you.
  • Disclosure is coordinated: we publish the details after the fix, or after 90 days at the latest, unless we agree otherwise. We are happy to credit you if you wish.

Supported versions

Security fixes ship in the newest release, which sites receive as an automatic update. For the previous minor version (for example 1.0.x when the latest is 1.1.x) we publish the fix only on GitHub Releases, as a signed zip, without an automatic update. Please update to the newest release before reporting.

How updates are protected

The plugin does not get updates from wordpress.org. It gets them like this:

  • Signed manifest. consent.rt.md serves one manifest per channel (stable and beta), with a detached Ed25519 signature. The manifest says which version is available, where to download it and the SHA-256 hash of the package. The plugin uses it only if the signature is valid.
  • Signed package. The zip comes from GitHub Releases. Before installing, the plugin checks the zip's SHA-256 hash and its Ed25519 signature. It accepts only the exact URL from the verified manifest. If anything does not match, the package is deleted and the update is refused.
  • Anti-rollback. The plugin remembers the newest manifest it has seen on each channel and refuses an older one. Nobody can serve you an old but validly signed manifest to keep you on a vulnerable version.
  • Expiry. A manifest is valid for at most 60 days. We re-sign it every month. An expired manifest offers no updates, and a notice appears in the admin.
  • Revoked versions. The signed manifest lists revoked versions. A revoked version is never offered. If you have one installed, a notice appears in the admin.
  • Without the PHP sodium extension signatures cannot be checked. The plugin then installs no updates and tells you why.

Verify a zip by hand

  1. From GitHub Releases, download consent-manager-pro.zip and consent-manager-pro.zip.sig of the same version.
  2. Compute the zip's hash and compare it with the sha256 field in manifest-stable.json (for the version in the manifest): 
    shasum -a 256 consent-manager-pro.zip
  3. Check the signature with the release key. The command must print OK: 
    php -r '$k = base64_decode("YeJZw3HBsttEaUxHNqbxC+13IewsPPbOyUOU08hkE8o="); $s = base64_decode(trim(file_get_contents("consent-manager-pro.zip.sig"))); $z = file_get_contents("consent-manager-pro.zip"); echo sodium_crypto_sign_verify_detached($s, $z, $k) ? "OK\n" : "INVALID\n";'

If you see an error, the .sig file is missing or wrong.

If a release was signed with the rescue key, put the rescue key in the command. If the check fails, do not install the zip, and write to us.
